# Grove art

Everything in this directory is original work for Grove, generated by
`tools/generate_art.py`. Nothing here is downloaded, traced or adapted from any
existing asset — no Metro City, no LimeZu, no Star Office, no Pixel Agents, no
sprite pack of any kind. See `LICENSE`.

To change any asset, **edit the generator and re-run it**. Do not hand-edit the
PNGs; the next run will overwrite them.

```
python3 apps/web/public/art/tools/generate_art.py     # rewrites the PNGs + manifest.json
open  apps/web/public/art/tools/preview.html          # served from apps/web/public
```

`tools/preview.html` lays the whole set out on a real isometric grid at 1×,
0.55× (where plot labels drop out) and 0.4× (minimum zoom), plus a contact
sheet. It has checkboxes for anchor crosshairs, sprite bounds and the legacy
ground tiles. Judge pixel art by looking at it, at the size it will be seen.

---

## Geometry

The world is a 64 × 32 isometric diamond grid: `TW = 64`, `TH = 32`.

`iso(tx, ty)` in the renderer returns the diamond's **north vertex** — not its
centre and not its bounding-box corner:

```
                 iso(tx,ty)  ← (x, y)
                    /\
      west  (x-32, y+16)  (x+32, y+16)  east
                    \/
                 (x, y+32)  south
```

A ground tile is drawn `ctx.drawImage(img, x - 32, y, 64, 32)`.

The generator works in **tile space**: `x` runs tile-east (`tx+1`, screen
down-right), `y` runs tile-south (`ty+1`, screen down-left), `z` runs up in
**pixels**. Horizontal distances are tiles, vertical distances are pixels —
mixing those up is the easiest bug to write here, and it has been written once
already (every lantern came out 1 px tall).

```python
proj(x, y, z) -> ((x - y) * 32, (x + y) * 16 - z)
```

## Anchor convention

**Every sprite declares one anchor pixel, and the renderer puts that pixel
exactly on `iso(tx, ty)` of the sprite's north-most footprint tile.**

```js
const p = iso(tx, ty);                       // north tile of the footprint
ctx.drawImage(img, ox + p.x - a.anchor[0],
                   oy + p.y - a.anchor[1], a.w, a.h);
```

That is the whole rule. It covers ground tiles, props and 4-tile buildings
identically. For a footprint of `fw × fh` tiles, structure height `Hz` px and
padding `pad`:

| | |
|---|---|
| width  | `(fw + fh) * 32 + 2*pad` |
| height | `(fw + fh) * 16 + Hz + 2*pad` |
| anchor | `[fh * 32 + pad, Hz + pad]` |

A ground tile is the degenerate case — `fw = fh = 1`, `Hz = 0`, `pad = 0` →
64 × 32, anchor `[32, 0]` — i.e. exactly the existing `tiles/*.png` draw call.

**Draw order.** Structures must be painted back-to-front by `(tx + ty)` of their
**south-most** footprint tile, interleaved with bodies. A 3 × 3 building whose
north tile is `(tx, ty)` sorts at `(tx + 2) + (ty + 2)`.

**Two exceptions, both deliberate:**

- `animals/*` are 64 × 64 and drawn through the **character** path, unchanged:
  `drawImage(img, x - 20, y - 20, 40, 40)` with `y = iso.y - 18`. Their feet sit
  on the bottom edge of the 64 px frame because that is where `chars/*.png` put
  theirs. Their manifest anchor is `[32, 62]` and they carry `"drawLike":
  "chars"`.
- `items/*` are 24 × 24 with anchor `[12, 12]` — the **grip point**, to be put
  wherever a body's hand is, not on a tile.

**Known mismatch, not mine to fix:** the renderer stands bodies at the tile's
*north vertex* (the feet-ellipse is drawn at `iso.y`), while anything with a
footprint covers the tile *diamond*, from `iso.y` to `iso.y + 32`. So a body on
tile *T* appears about half a tile north of a prop on tile *T*. Everything here
is internally consistent; if you want a body to look like it is standing *on* a
bench, seat it one tile north of the bench.

## Palette

Sampled from the existing `tiles/` and `chars/` so new art sits in the same
dusk, then extended. The authoritative list is `palette` in `manifest.json`;
the generator's `PAL` dict is the source.

| role | | |
|---|---|---|
| ground / night | `#0b0d18` `#03022a` `#070814` | the dusk the whole thing sits in |
| stone | `#242236` `#3e3a5c` `#5e5680` `#7e5e75` | plaza, library, walls |
| wood | `#2c1d18` `#623e32` `#8a5a45` `#b07a58` | stage, workshop, scaffold |
| leaf | `#0f2e2b` `#184542` `#2a6b60` `#4d9c7a` | garden, wild ground |
| lantern amber | `#8a5a22` `#e8b86d` `#f4d19a` `#ffeec4` | every light source |
| agent violet | `#3c2e70` `#7c5cd6` `#a78bfa` | library roof, curtains, agent identity |
| road | `#262336` `#564e64` `#7c7088` | paths, so they separate from grass *and* paving |

**The three access accents are not decoration.** They are the same hues the
renderer already tints claimed ground with (`PRESET_TINT` in `WorldMap.tsx`), so
a building and the ground under it say the same thing in the same colour:

| access | hex | where it appears on the building |
|---|---|---|
| `private` | `#f472b6` | roof ridge, the bar across the gate, the two lamps |
| `public_view` | `#38bdf8` | frieze band, roof ridge, the rail across the front |
| `public_write` | `#fbbf24` | canopy ridge, the scalloped valance |

Use the accent as an **accent**. An early pass gave the private building an
entirely pink roof and at 0.4× it read as a circus tent, which drowned the wall
— and the wall is the message.

## How the three access levels say what they are

The permission is the point; the architecture is how it gets said. Each has to
be distinguishable by **silhouette alone**, because at minimum zoom that is all
there is:

- **`private` — a solid block.** An unbroken wall with crenellations, a keep
  filling the space behind it, a shut two-leaf gate barred across. Nothing shows
  through the outline. There is no way in and the shape says so.
- **`public_view` — a comb.** A colonnade: eight columns with lit gaps between
  them, a warm floor and furniture visible through the gaps, and one unbroken
  rail across the front. You can see the whole interior and you cannot walk into
  it. *(The roof is a shallow hip for this reason — a flat plate hid the
  colonnade completely from this camera, and the colonnade is the statement.)*
- **`public_write` — a canopy on legs.** Four posts, no walls at all, broad
  steps on both viewer-facing sides, a table and benches under a lit lantern.
  Ground shows *under* the roof. Walk straight in.

## Adding a new asset

1. Write a `build_*` function in `tools/generate_art.py`. Use `Sprite(fw, fh,
   hz, pad)` and draw with `box`, `hip_roof`, `gable_roof`, `post`, `poly`,
   `line`, `dither`, `glow`, `shadow`. The anchor is computed for you.
2. Register it in `main()` with a `file`, a footprint, and a **`reads_as`**
   string saying what the thing is *for* — which access level, which room,
   which stage. An asset nobody can tell the purpose of is not finished.
3. Re-run the generator. `manifest.json` is rewritten from the build, so the
   manifest can never drift from the PNGs.
4. Open `tools/preview.html` and look at it at 0.4× as well as 1×.

House rules that came out of doing it wrong first:

- **Vertical is pixels, horizontal is tiles.** Always.
- **Calm ground, loud buildings.** Ground texture is what you notice least and
  it is where noise does the most damage: a whole region of speckle reads as
  scree at 0.4× and swallows everything standing on it. Keep ground dither
  below ~0.06 density and inside a 2-3 step value range.
- **Glow is drawn in paint order, not depth order.** `glow()` composites over
  whatever is already on the canvas, so call it *before* anything that should
  occlude it. A bloom called after the roof lands *on* the roof.
- **Never let a cuboid corner show on something organic.** Foliage built from
  one box reads as a crate; it takes overlapping lumps plus notched corners.
- **Outline everything structural** (`outline="ink"`), and leave organic things
  un-outlined so they stay soft.
